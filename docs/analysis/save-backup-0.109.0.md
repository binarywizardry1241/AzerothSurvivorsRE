Target: installed Windows0.109.0 EXE, SHA-256 `76e7fb483ce65a43e3d54cb85fe87e250a28b052dc3a3be01332741b4c932fb0`.

Ordinary persistence now tests the normalized typed Save for progress. The old raw-prefix test incorrectly treated unknown/malformed rows and zero-only counters as progress. Native `1458a33c0` compares the parsed Save against its typed default after attempting the active-file write; a nonempty canonical serialization agrees with this gate in all27 retained cases. Empty equipment-class rows, zero-XP talent/spec rows and explicit default pets remain meaningful typed records and still qualify. The canonical parser/serializer is owned by [Save schema](save-schema-0.109.0.md), and the cryptographic envelope by [Save envelope](save-envelope-0.109.0.md).

The same current ordinary-write owner is canonical in [summary-save.asm](evidence/0.109.0/run-account/summary-save.asm); its bytes are not duplicated. Fresh REA/Ghidra recovery confirms serialize → seal → reopen/compare → active write → typed-default gate → backup clock admission. A failed active write does not bypass the later backup attempt. Seal round-trip failure falls back to plaintext. Active writes create the parent on a best-effort basis and directly create/truncate/write the destination; this is not an atomic-rename contract. The existing source connects those branches.

Backup admission remains due when the prior timestamp is absent/unparseable, later than the current clock, or at least3,600 seconds old. A successful backup writes `Saves/Backup YYYY-MM-DD HH-MM-SS.sav`, scans matching names and keeps the lexically newest five. The exact-case filter requires the `Backup ` prefix, `.sav` suffix and a valid UTF-8 filename; no file-type test is added. Paths are sorted using the native Path comparator. Native cleanup attempts the removed portion in descending order; source now preserves that order. Per-file cleanup errors do not invalidate the created backup. Directory creation and backup-write failure return failure and leave the timer unchanged; a successful backup advances `characters.backup-at.txt`, whose write failure is ignored. Exports do not use this timer.

The [manifest](evidence/0.109.0/save-backup/manifest.json) binds both newly retained backup/filter owners, fresh Ghidra identities, the canonical ordinary writer and each additionally admitted pure helper. Ghidra's raw-carrier ABI is provisional; original Win64 instructions govern argument, register and field interpretation. Shared active-path/auxiliary-file helpers retain their existing canonical evidence in the [Saves browser](saves-browser-0.109.0.md) and [HUD storage](run-hud-0.109.0.md) reports.
