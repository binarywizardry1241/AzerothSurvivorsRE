## Removal and failure boundaries

The current Options site `0x1400b18a0` forwards its Location to the 8-byte helper
`0x1400d48d0`. The producer at `0x1400b13d0..0x1400b147b` searches Options'
8-byte-key vector, removes the first present key, or appends an absent key.
The existing `Action::BindingHeader` toggles expanded-header membership with
the same present/absent behavior. Its source set representation does not claim
the native vector's storage order. Fifty-four original-instruction cases verify
the selected membership decision, first index and absent-key insertion.
The ability site `0x145933b58` forwards its Location to the
120-byte helper `0x1459bf5e0`. Its current producer
`0x145933a8a..0x145933bad` counts equal ability keys in the Game+600 totem
vector. At **40 or more** matching rows it removes exactly the first match,
then expires the removed totem before constructing the replacement. The
existing `totems::remove_for_kind_limit` and `dispatch::cast` already implement
this threshold, stable selection and ordering. Twenty-eight original-instruction
cases cover 0/1/2/39/40/41/80 equal-key rows, two key lengths, same-length
different keys and interleaved nonmatching rows. No source change is required.
These source connections do not certify all descriptor storage, row identity,
ownership, source language execution or whole totem creation/tick parity.

The 120-byte helper checks the removed row's leading word **after** shifting
and decrementing length. A zero leading word reaches its refusal interface
with the already reduced length. Treating that caller as an immediate panic
site would lose this ordinary state transition. The checker covers that
ordering explicitly.

The other 97 sites reach failure interfaces, independently identified by their
current call targets, helper instructions and failure strings. Shared panic,
formatter, ECS and allocator internals are supporting context where this branch
stops. Such a failure-path Location does not establish the successful index
producer, resource lifetime or complete AS mechanic. The existing owning gaps
and source reports retain those obligations, including #11/#42/#58/#63/#71.
This classification establishes no additional missing gameplay operation and
makes no source repair or completeness claim.
