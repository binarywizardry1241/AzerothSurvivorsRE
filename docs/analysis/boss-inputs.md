## Current layout and formulas

The twelve zone rows start at `146bde390` with240-byte stride. Boss pointer/count
are at zone+`88`; each current boss row is104bytes. Name is at+0, recurring list
at+16, yell at+32, phase list at+48, ID at+64, model at+68 and scale at+72.
The remaining fields preserve their semantic source roles: raw constructor
field+76, schedule minutes+80, baseHP+84, base damage+88, movement scalar+92,
sound+96 and final-boss flag+100.

Current constructor fragments `14596dab9..14596db66` and
`14596dec9..14596e028` retain the native f32 rounding/order. Health is based on
`baseHP ×5.75 ×zoneScale ×difficulty ×endlessHealthFactor`, then the selected
health percentage. Damage uses `sqrt(zoneScale×difficulty) ×baseDamage
×endlessDamageFactor`, then the selected damage percentage. Speed uses the
selected speed percentage and the boss's raw movement scalar. Reach is
`min(scale×1.5+3.5,9)`; the actor attack period is2s.

The current endless power calls occur only when phase==1 and endless is enabled.
The exponent is `max((rawClock−endlessStart)/60,0)`. The native caller requests
damage `powf(1.096,exponent)` first, then health `powf(1.22,exponent)`; all other
states use exact1 factors without power calls. `bosses/scaling.rs` now preserves
this gate and call order. Its earlier implementation called both powers in
every state and reversed their order. The remaining checked constructor
arithmetic already agreed.

Boss initial recurring timers retain repeat×0.6. The separate native replacement
list helper initializes repeat×0.5+1. Boss enrage latches when health is strictly
below the rounded maximum×0.3 and scales recurring repeats by0.7. Guardians use
their separately recovered nonlatched current-health rule. Phases use strict
health-ratio thresholds and original entry-index latches before recurring
requests; the canonical phase gate cases remain with the tower/guardian owners.

## Checks and limits

```sh
python3 -B scripts/check-boss-inputs.py
```

The check passes sixty exact semantic headers and480 original arithmetic cases
(sixty bosses×eight profiles), including percentage extremes, inactive endless
states with injected non1 factors, elapsed endless time and a clamped zero
exponent. It executes the current caller instructions with explicit injected
Windows `powf` results, checks their gate/order and compares output f32 bits.
It also executes all five current replacement-list timer inputs and six empty,
scalar/SIMD-boundary profiles (0/1/7/8/9/16 children) through the native helper,
with only allocation intercepted. The actual timer bits agree with repeat×0.5+1.
The canonical helper assembly remains in the raid-native evidence directory.
The current Rust regression reads these target-specific arithmetic vectors;
historical vector replay retains its actual old inputs while applying current
call admission. These regressions were authored and parsed, not compiled/run.
The fixtures do not implement or certify the Windows power library. Enrage, phase-ratio
and recurring assembly are separately inspected and are not counted as extra
executed arithmetic cases.

Source guards and `rustfmt --emit stdout` parsing do not establish compilation.
No compiler, compiling tests, game process, rendering/audio comparison or
original/rebuilt gameplay validation was run. This report verifies bounded
input/arithmetic reconstruction; spawning position, full actor constructors,
publication and shared engine behavior retain their owning evidence limits.
