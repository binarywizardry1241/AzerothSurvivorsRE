## Recovered contract

The ordinary `SetRaidTarget(unit, index)` binding queues a party intent. The
existing engine resolves the selected unit and converts Lua marks 1–8 to wire
icons 0–7; clearing sends the unit's current icon with GUID zero. Its production
command previously fell through the offline request bridge's wildcard and was
discarded. No mark response ever reached the existing group/UI consumers.

Current native request owner `0x145873b00`, opcode `0x321`, reaches the local
host's eight-slot board at `+0x1750` independently of optional Game presence,
party membership, leadership, run start, pause or world readiness. The separate
cooperative sender-admission and transport branch is outside this repair.
The first request byte selects an icon. Missing bytes are read as zero, up to
eight following bytes form the little-endian GUID, and trailing bytes are ignored.
Byte `0xff` requests the current full list without changing the board.

Board owner `0x145824040` ignores icons 8–254. For a nonzero GUID it first clears
matching GUIDs from every other slot in ascending slot order, then changes the
selected slot if necessary. It appends the selected slot **last**, even when its
index is smaller. GUID zero clears only the selected slot. Redundant assignments
emit no delta, except that existing duplicate slots still need clearing.

For example, board `[1,2,3,4,5,6,7,8]`, icon 0, GUID 7 yields changes `[6,0]`:
first clear slot 6, then set slot 0 to 7. The sender reads the final board value
for each changed slot and emits one packet per change.

- Delta owner `0x1459ab120`: opcode `0x321`, body `00`, icon byte, GUID u64le.
- List owner `0x1459ac910`: same opcode, body `01`, then nonzero icon/GUID pairs
  in ascending slot order; an empty board is the single byte `01`.

The full list owner's range ends at `0x1459acab9`; `0x1459ac9b9` is inside the
function and does not cover its serializer or return.

The current host replacement path clears all eight slots at
`[0x14588cff7,0x14588d03b)` and serializes the empty list before publishing its
replacement Game. Login's `[0x1458865fd,0x145886617)` instead serializes the
existing board unchanged. Login does not remove duplicate GUIDs. These excerpts
are tested separately; no surrounding host/service implementation is substituted.

## Popup and connected source

Current patch owner `0x145996550` reads `Interface\\FrameXML\\WorldStateFrame.lua`,
concatenates its existing content, the patch descriptor at `0x1473366f0` and the
API generated by `0x1458494a0`, then supplies the patched core content. The patch
descriptor points to `0x147333bd4` with length `0x2b1a`. The exact selected
[popup fragment](evidence/0.115.0/raid-targets/popup.lua) is file range
`[0x7334dd4,0x7335112)`. Other portions of the packed patch are not copied here.

The wrapper calls stock `UnitPopup_HideButtons` first and changes only menu
entries whose first twelve characters are `RAID_TARGET_`. It enables those
entries, then hides them when the menu is not SELF and the current target is an
existing player who is outside the party, cannot cooperate with the player and
is not the player. The source uses these exact predicates, including their
current-target semantics, rather than substituting a general friendliness test.

`gameplay/client/raid_targets.rs` appends that immutable fragment to the same
core file, after the existing core additions and before external addons. The
loader applies every matching append, including on replacement VMs. The ordinary
FrameXML click/toggle and key binding routes still call the existing engine verb.

`benilla-app/local_client/requests.rs` now forwards the real command's icon and
full GUID. `gameplay/mod.rs::resolved_requests` handles that verb in its existing
ordered drain, checks local-channel activation and forwards the authoritative
responses. It does not add a Game or party gate. Unrelated requests keep their
order; inactive-channel requests drain without changing the board.

The board reset runs in `First`, after the client bridge publishes a new local
session and before `LocalClientSet::Lifecycle`. Its packet therefore reaches
normal Update dispatch before the first new-run unit snapshots can read stale
marks. The ordinary request drain still follows native logout handling. Reset
publishes an empty full list when the successful run identity changes. Identity advances only after mechanics creation succeeds;
failed creation retains the previous board. Ordinary ticks, pause and ReloadUI
do not clear it. No renderer or addon maintains a competing authoritative board.

Both response forms pass through the real `parse_server(0x321, ...)` decoder and
existing `SessionEvent` dispatch. `GroupState` applies them and signals
`RAID_TARGET_UPDATE`; normal unit snapshots expose the mark to
`GetRaidTargetIndex`, TargetFrame, nameplates and the existing world raid-icon
renderer. Artwork, geometry and the shared engine's token resolver remain reused.
This source trace does not certify all generic engine token/ABI behavior or
rendering against the current target.

## Validation and limits

```sh
python3 -B scripts/check-solo-raid-target.py
```

The check passes **13,530 native cases**, **128 popup cases** and fourteen live
source-inspection guards. It replays the original board, local request and serializers with synthetic
state in Unicorn, checks the current native lifecycle excerpts, verifies the
exact retained popup bytes, runs its predicate truth table in standalone Lua,
and inspects the live source connections. Rust allocation/free, byte-vector
growth and final packet delivery are explicit replay seams. No cooperative
branch or original application executes.

`--prepare-rea` writes a portable durable query plan and seeds under ignored
`runtime/`; invoke that plan through `./scripts/rea query <plan.json>` when
reproducing native analysis. Retained function/excerpt/assembly/descriptor hashes
and the complete replay proof are checked on every ordinary checker run.

Four Rust modules were syntax-parsed without compilation. Four meaningful Rust
regressions are authored but uncompiled/unrun: command projection, duplicate
cleanup/decoder results, replacement/same-identity/inactive board lifetime and
mixed request ordering/Game-independent/inactive delivery. The independent
source review also checked system ordering and the loader's multiple-append path.

Compilation, actual ECS/VM execution, popup clicks, target-frame/key/macro actions,
nameplate/world icon display, pause/new-run/ReloadUI behavior and original/rebuilt
functional or visual parity remain unverified. Current Ghidra request-dispatch
pseudocode has unresolved computed-table boundaries; exact assembly and bounded
instruction replay establish the selected branch, not the entire dispatcher or
engine. Broader native/type/alias/source recovery remains #41. No build, compiling
test, game launch, networking, server operation or installed-game write ran.
