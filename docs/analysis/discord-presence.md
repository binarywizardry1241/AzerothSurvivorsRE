# Discord activity,

The installed Windows 0.109.0 executable (SHA256 `76e7fb483ce65a43e3d54cb85fe87e250a28b052dc3a3be01332741b4c932fb0`) owns an actual Rich Presence publisher. It is separate from the community button and its bitmap. The previous source exposed the archived `discordPresence` option but supplied no publisher or activity snapshot. That missing consumer is now connected through `discord.rs`, `gameplay/discord.rs` and the [current transport](discord-transport.md).

## Recovered owners

The [manifest](evidence/0.109.0/discord-presence/manifest.json) binds seven instruction ranges and six Ghidra queries to the selected EXE. The activity builder is `14006b460`; its ECS publisher is `14007b510`; JSON equality is `14007de60`. The current game-definition serializer `145928330`, meter serializer `14599cb60`, floating-field adapter `1458e6790` and number formatter `1458edff0` establish the live inputs. Transport owners and spawn-route helpers have one canonical copy in the linked transport report.

The publisher registers archived `discordPresence=1` once. On its first call, and subsequently at least one elapsed second apart, it reads the CVar, trims whitespace, and treats exactly `0` as disabled. Other strings enable activity. It compares the complete optional activity against its previous value. The first nonempty activity lazily starts the named worker; later changes, including `None`, go through the same channel. The worker's four-second send throttle, reconnect and pipe-close behavior have separate transport ownership.

The menu activity describes the selected hero, translated race/class and next zone. A run requires its entry definition; it supplies hero/race/class/zone/subtitle, current level/kills and the localized class key used by the exact external class-icon URL format. Unknown class names omit both small asset fields. The browser button uses `https://wow.aethus.pl/` with its translated label.

Run state priority is terminal summary, ready/paused/dead, current boss object, reward choice, endless, survival. A terminal summary overrides level/kills when those fields are numeric. Only its exact type `victory` selects the trophy text. Boss health percent uses `hp*100/max(hpMax,1)` without clamping the resulting percentage; a missing name uses the translated `a boss`, while an empty name stays empty. Kills are saturated/truncated unsigned integers with ASCII comma grouping. Level has minimum one.

The small asset text uses the localized class name and the leading meter name. The builder scans `meter[].dmg` with total float ordering; the last equal value wins. Its DPS is the separately published total `dealt/max(time,1)`, not that row's damage. Rates below 1000 use zero decimals; others use one decimal plus `k`. The `leads, … DPS` suffix is literal native text. The current game serializer rounds each damage row and the total before publication, and formats finite floating scalars to three decimals. The source projection preserves these intermediate JSON values and reuses the existing phase/localized damage-name owners.

Menu/inactive phases clear the cached timestamp. Active boss/choice/endless/survival phases use `epoch - trunc(run.time)` and retain the previous start while drift is less than four seconds. Disabling the CVar bypasses the builder, so it does not independently clear that cache. Missing entry similarly returns no activity without changing it.

## Source connection and checks

`DiscordPlugin` polls after Options input and the coherent run presentation snapshot. The gameplay child captures the entry JSON once, preserves it through Again, and clears the complete activity snapshot on Logout/return to menu. The frontend in-run latch and previous live/terminal values survive an absent replacement Game, so Again does not briefly publish menu activity. The [shared Screens poll](evidence/0.109.0/menu-fidelity/frontend-poll.asm) `140191820` proves this lifetime: ready reads `restart` at `140192c29`; a non-null restart preserves an existing entry, and logout clears it at `140192886`. Language changes during a run do not rewrite those retained strings. The gameplay child projects the existing mechanics and terminal resources: the first living primary boss, translated names, localized damage accounting, current phase, rounded total and terminal result. It performs no combat or account mutation. The existing Options registration supplies the recovered CVar/default and its persistence; the publisher reads that live mirror.

`python3 -B scripts/recover-discord-presence.py --check` passes 139 unchanged native activity executions and 10 unchanged native number-format executions. Cases include phase/boss precedence, terminal overrides, malformed/missing fields, meter ordering/ties/rates, timestamp drift/reset, all nine classes, eight races, twelve zones and thirteen non-English languages. Explicit seams cover host allocation/strings, JSON storage operations, translation/argument formatting, time, and localized descriptor/zone lookup. Class/race by-ID leaves execute directly against current PE data. The retained compact vectors also drive meaningful Rust builder tests, which have **not** been compiled or run.

The full publisher ECS/channel/scheduler and the game/meter serialization owners were statically reviewed; these are not represented as executed by the activity fixture. Rustfmt parsing and scoped whitespace checks passed. No build, game, audio/device, network/IPC server or Discord client ran. Actual Bevy ordering, live run projections and Windows Discord display still need build/runtime validation. The Windows artifact supplies no Unix socket discovery; the [transport report](discord-transport.md) records that explicit portability boundary.
